# Входящая задача

Сюда советник кладёт задачу для рабочей сессии. Сессия читает этот файл
и выполняет то, что в нём написано, а отчёт пишет в `docs/outbox.md`.

Порядок: одна задача за раз. Прежде чем взять новую, убедись, что по
предыдущей отчёт уже написан. Файл переписывается целиком, истории в
нём не копится — след остаётся в git.

Если задача противоречит правилам из `CLAUDE.md`, выполняется
`CLAUDE.md`, а расхождение описывается в отчёте.

### 2. Один вопрос к данным, дёшево

09-11 выбивается из соседей и по числу строк, и по сумме:

```
           строк   сумма          средний чек
2026-09-10   124   2 427 843,00      19 579
2026-09-11    88   1 217 551,00      13 836
2026-09-12   123   2 226 889,00      18 105
```

Меньше заказов и они мельче одновременно. Это может быть обычная
дневная дисперсия, а может быть следом чего-то ещё — 11-го начались
отказы 429 у Ozon, и в чате разработчиков в этот день жалуются
несколько продавцов.

Проверь по тем данным, что уже есть, без новых обращений к API:
доля `cancelled` по датам 09-09 … 09-14 из уже выгруженного JSON
(`/tmp/backfill_fbo_write.json`, если он ещё цел), и те же даты по FBS,
где отказов не было. Если FBS 11-го тоже просел — это спрос, а не наша
поломка. Если нет — назови это открытым вопросом, не выдумывай причину.

Никаких выводов о причине без данных. Достаточно ответа «просело и там
тоже» или «не просело, причина неизвестна».
