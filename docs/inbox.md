# Входящая задача

Сюда советник кладёт задачу для рабочей сессии. Сессия читает этот файл
и выполняет то, что в нём написано, а отчёт пишет в `docs/outbox.md`.

Порядок: одна задача за раз. Прежде чем взять новую, убедись, что по
предыдущей отчёт уже написан. Файл переписывается целиком, истории в
нём не копится — след остаётся в git.

**Пока задача в работе, советник этот файл не трогает.**

Если задача противоречит правилам из `CLAUDE.md`, выполняется
`CLAUDE.md`, а расхождение описывается в отчёте.

### 2. Застрявшие строки — механизм, а не ручная чистка

Три таблицы копят ключи, которых у Ozon уже нет, потому что upsert не
удаляет: `marketplace_expenses` (4 за 9 дней, +1 667,25, §9-4е), `marketplace_buyouts`
(08-21 sku 4453045714, 5 930,50) и по построению `ozon_accrual_daily_types`.
Правило одно для трёх: **после полного сбора окна удалять ключи окна,
которых нет среди построенных строк** — как у заказов FBO.

Обязательные защиты, без них не делать: удаление только внутри окна
сбора; только если сбор полон — все страницы получены, отказов и 429
не было (`docs/loader_partial_data_contract.md`: частичный ответ с
удалением превратил бы дыру в API в дыру в базе); список удаляемых
ключей печатается целиком до удаления; удаление после записи, не до.
Сначала — сухой прогон по живой базе: какие ключи ушли бы сегодня по
каждой таблице (ждём 4 + 1 + 0, каждый с датой и суммой; иное —
объяснить). Тесты: частичный сбор → удаления нет; полный → удаляются
ровно ключи вне построенных; ключи вне окна не трогаются никогда.
Ветка, мерж — по слову владельца блоком «вопрос, задача не закончена»;
первое настоящее удаление случится ночью — назови в отчёте, что именно
удалится, чтобы утром 09-23 это сверить.
