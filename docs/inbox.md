Сюда советник кладёт задачу для рабочей сессии. Сессия читает этот файл
и выполняет то, что в нём написано, а отчёт пишет в `docs/outbox.md`.

Порядок: одна задача за раз. Прежде чем взять новую, убедись, что по
предыдущей отчёт уже написан. Файл переписывается целиком, истории в
нём не копится — след остаётся в git.

Если задача противоречит правилам из `CLAUDE.md`, выполняется
`CLAUDE.md`, а расхождение описывается в отчёте.

## Потом: себестоимость, проверка стыковки

Владелец дал файл себестоимости — его не было в системе никогда.
Положен в `data/cost_20260520.xlsx`. Это выгрузка из 1С на 2026-05-20,
один снимок, истории изменения цены нет.

**Ничего не строим и не пишем в БД.** Задача одна: выяснить, стыкуется
ли этот файл с нашими данными и на каком ключе. Пока это не известно,
строить `article_unit_costs` рано.

### Что в файле (разобрано советником, перепроверь)

```
строк                28 965, лист TDSheet, 39 колонок
Себестоимость        заполнена везде, 70,03 … 374 711,33 ₽, нулей нет
```

Ключи к Ozon в каждой строке — **три** offer_id на одну позицию:

```
Идентификатор Ozon    F007752682-ИЗгт    основной
селект Ozon           S007752682-ИЗгт    Ozon Select
дискаунтер Ozon       T007752682-ИЗгт    дискаунтер
```

Всего уникальных offer_id Ozon: 86 799.

Числовой SKU лежит в `Внешний идентификатор Ozon`, но заполнен только
у 14 041 строки из 28 965, и местами содержит два значения через `;`
(например `3076902915;533048038`).

### 1. Проверка стыковки — главное

Возьми из `marketplace_orders` (или из того, что строит витрины) все
различные ключи товара Ozon за последние 90 дней и посчитай:

- сколько находится в файле по `offer_id` (по всем трём колонкам);
- сколько находится по числовому SKU (`Внешний идентификатор Ozon`,
  с разбором значений через `;`);
- какой ключ даёт большее покрытие;
- сколько НЕ находится ни по одному — и какую долю выручки эти
  ненайденные составляют. Доля выручки важнее доли строк: сто редких
  артикулов весят меньше десяти ходовых.

Верни числа, а не вывод. Список первых 20 ненайденных с выручкой.

### 2. Две неоднозначности, которые надо описать, а не решать

**`Себестоимость` против `единая`.** Различаются в 22 893 строках из
28 965. `единая` — одно значение на артикул (у 7 413 артикулов из 7 557),
`Себестоимость` — на конкретный вариант «артикул + размер + вставка».
Опиши разницу на примерах и скажи, какая из них ложится на наши ключи
без потерь. Выбор сделает владелец.

**33 offer_id с двумя разными себестоимостями.** Например `F007742409`
→ 5 025,93 и 5 171,37. Найди их все, покажи список. Не усреднять и не
выбирать — назвать.

### 3. Чего в файле нет — зафиксировать

- истории: одна цена на 2026-05-20, значит маржа за март и за сентябрь
  считается по одной себестоимости, хотя металл дорожает;
- составляющие (`СС_СтоимостьМеталла` и прочие) не сходятся с итогом в
  16 355 строках, расхождения разные (1 695 различных значений). Для нас
  это неважно — берём итог, — но записать надо.
