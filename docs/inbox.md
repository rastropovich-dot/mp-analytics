# Входящая задача

Сюда советник кладёт задачу для рабочей сессии. Сессия читает этот файл
и выполняет то, что в нём написано, а отчёт пишет в `docs/outbox.md`.

Порядок: одна задача за раз. Прежде чем взять новую, убедись, что по
предыдущей отчёт уже написан. Файл переписывается целиком, истории в
нём не копится — след остаётся в git.

**Пока задача в работе, советник этот файл не трогает.**

Если задача противоречит правилам из `CLAUDE.md`, выполняется
`CLAUDE.md`, а расхождение описывается в отчёте.

### 3. Дефект резюма — починить, но не включать

`CLAUDE.md` §5 описывает корень:

    validate_cpc_resume_progress            ~1556
    resolve_existing_cpc_backfill_progress  ~2208

Обе требуют `date_from == date_to == target_date`. Прогресс по
многодневному окну пишется, но прочитать его нельзя, поэтому правило
«не начинать recovery с batch 0, если есть partial progress»
неисполнимо, и воркер выключен. Номера строк от 09-13 и уже сместились
однажды — искать по именам функций.

Почини на ветке `recovery-resume-multiday`: чтение прогресса по
многодневному окну, тесты на резюме с середины окна и на то, что batch 0
не повторяется. Тесты обязательны — это код, который ходит в API за
деньгами квоты, и проверять его на проде дорого.

**Не включать.** Флаг `--skip-recovery` не трогать, в `main` не мержить,
живых вызовов не делать. Включение — отдельное решение владельца после
чистой ночи. Напиши в отчёте, что именно нужно сделать для включения и
чем это рискует.
