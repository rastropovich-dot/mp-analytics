### §3. Источник сводных — только колонки источника владельца, без полей группировки

Советник разобрал `pivotCacheDefinition` его трёх сводных: `Месяцы` (WB, заказы), `Дни (Дата начисления)` и `Месяцы (Дата
начисления)` (Ozon) — **поля группировки сводной** (`fieldGroup base=… <rangePr groupBy="days|months">`), Excel строит их
сам из «Дата» / «Дата начисления»; в источнике владельца их нет: у Ozon 13 колонок (ID … Наименование), у WB 14
(Дата … Статус), у заказов 29 (0 … 20 и 22 … 29, «Месяцы» — 21-е поле кэша, сгенерированное). В наших «Данных» эти
имена — настоящие колонки внутри `ref` сводной, при пересчёте они сталкиваются с группировкой (то же имя) — вероятная
причина, что группировка по дням ломается. Сделать:

1. `worksheetSource ref` — ровно колонки источника: Ozon `A1:M…` (13), WB `A1:N…` (14), заказы `A1:AC…` (29) — для
   этого в «Данных заказы» перенести колонку «Месяцы» из 22-й позиции в конец владельческих (после «Фин.рез %», перед
   нашими `SKU/nmId` …); в «Данных Ozon выкупы» и «Данных WB выкупы» колонки «Дни …» / «Месяцы» уже последние из
   владельческих — из `ref` просто исключить, в листе оставить (справочно). `cacheFields` с `fieldGroup` не трогать
   (пересчёт создаст группы заново), `rangePr` — без `startDate` / `endDate` или с `autoStart="1" autoEnd="1"`, чтобы
   диапазон дат взялся из данных (у владельца 04-01 … 09-21, у нас до 09-24 и дальше).
2. Проверка как в 38-й (zip, XML, `r:id`, шапка `ref` = `cacheFields` без групповых, число строк) плюс: в `ref` нет
   колонок с именами групповых полей. Живой пересчёт — у владельца в Excel; ему одной строкой: на «Сводная WB выкупы»
   месяц раскрывается в дни — да / нет.
3. `docs/reports_model.md` — исправить описание «Данных»: 13 / 14 / 29 колонок владельца + наши; «Месяцы» / «Дни» —
   группировка сводной.
