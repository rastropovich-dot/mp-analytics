и выполняет то, что в нём написано, а отчёт пишет в `docs/outbox.md`.

Порядок: одна задача за раз. Прежде чем взять новую, убедись, что по
предыдущей отчёт уже написан. Файл переписывается целиком, истории в
нём не копится — след остаётся в git.

**Пока задача в работе, советник этот файл не трогает.**

Если задача противоречит правилам из `CLAUDE.md`, выполняется
`CLAUDE.md`, а расхождение описывается в отчёте.

Сегодня разбор ночи. Только чтение: **к Ozon API не обращаться, в БД не

### 1. Отработал ли ночью новый код

Три признака в данных, каждый — только от нового кода:

* `observed_at` заполнен у строк Ozon и остался null у WB;
* `cancelled_orders_qty` больше нуля хоть где-то;
* по FBS есть строки за даты глубже 14 дней от 09-18 — окно стало 30.

Если хоть один не выполнен, дальше не гадать: посмотреть деплой и лог
прогона через Render API (`RENDER_API_KEY` в `.env`, ориентиры в
`CLAUDE.md` §1) и сказать, какой код реально катился ночью.

### 2. Сошлось ли предсказание

Снимок владельца 2026-09-17 19:00 UTC, окно `order_date` 09-03 … 09-16,
`marketplace_code = 'ozon'`, до ночи:

```
схема   строк    qty     отмен
fbo     1 666   1 917      0
fbs     2 590   3 679      0
```

Чего я жду и почему — правила были разные, поэтому и ожидания разные:

* **FBS.** Старый загрузчик статус не смотрел, значит 3 679 — это уже
  «созданные», отменённые внутри. Новое правило их только разложит:
  `orders_qty + cancelled_orders_qty` должно остаться ≈ 3 679, а
  `orders_qty` — упасть.
* **FBO.** Старый отменённые выбрасывал, значит 1 917 — «подтверждённые».
  `orders_qty` должен остаться ≈ 1 917, отмены добавиться сверху, сумма
  пары вырасти.
* Доля отмен: заказам в окне от 2 до 15 дней, кривая дозревания даёт
  25–35 %. Это вилка, а не число.

Что считать поломкой, а не отклонением: у FBS сумма пары заметно уехала
от 3 679; у FBO упал `orders_qty`; `cancelled_orders_qty` везде ноль.

Посчитай фактические доли отмен по обеим схемам и сравни с вилкой. Если
доля вне 25–35 % — не подгоняй объяснение под вилку, вилка моя и
грубая; скажи, что вышло, и проверь по `ozon_posting_status_log`,
сходится ли доля с наблюдёнными переходами в `cancelled`.
