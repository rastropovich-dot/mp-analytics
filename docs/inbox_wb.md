# Входящая задача — WB

Сюда советник кладёт задачу для рабочей сессии по Wildberries. Сессия
читает этот файл и выполняет то, что в нём написано, а отчёт пишет в
`docs/outbox_wb.md`. Правила обмена те же, что у Ozon-потока
(`docs/how-we-work.md`, раздел «Порядок обмена»): одна задача за раз,
файл переписывается целиком, пока задача в работе — советник его не
трогает; вопрос посреди задачи — в `outbox_wb.md` блоком «вопрос, задача
не закончена».

`docs/inbox.md` и `docs/outbox.md` — канал Ozon-сессии. Не читать как
задачу и не писать туда.

### 2. Карта ручного листа «WB - сентябрь» на API

Цель следующих задач — лист «WB - месяц» в той же книге, что Ozon, и
приёмка `--check` по ручному листу. Сначала карта, без кода. Файл владельца —
`../mp-analytics/data/manual_report_september_20260922_v2.xlsx` (читать, не
копировать), лист «WB - сентябрь», колонки как у Ozon: Дата реализации,
Оборот (с НДС), Комиссия (с НДС), Комиссия %, Выручка, Себестоимость, Маржа,
Логистика, Реклама, Эквайринг, Прочее, Фин. рез., Ebitda. Формулы владельца:
Выручка = (Оборот − Комиссия) / 1,22 − «НДС за возмещение» (внешняя книга
«свод», колонка AB; за 1…21 сентября вычет 88 946,47), Фин. рез. = Маржа −
Логистика − Реклама − Эквайринг − Прочее, Ebitda = Фин. рез. − 74 002,00 в
день (ячейка T81). Итоги 1…21 сентября: оборот 16 667 220,00, комиссия
6 994 883,75 (42 %), выручка 7 839 198,00, СС 5 943 927,07, логистика
207 256,16, реклама 0,00, эквайринг 332 324,01, прочее 65 971,76, фин. рез.
1 289 718,99, Ebitda −264 323,01.

Для каждой колонки написать в `docs/wb_report_model.md`: эндпоинт и поле
(по `spec/wb/`: `13-finances.yaml` — `/api/finance/v1/sales-reports/detailed`,
`08-promotion.yaml` — `/adv/v3/fullstats`, что ещё нужно), какой датой
считается «дата реализации» (`sale_dt` / `rr_dt` / другое — назвать по спеке),
как из полей отчёта складываются Оборот, Комиссия, Логистика, Эквайринг,
Прочее и что такое «возмещение», с которого вычитается НДС; что уже есть в
наших загрузчиках и таблицах (`wb_sales_loader`, `marketplace_buyouts`,
`marketplace_expenses` по WB) и чего нет. Себестоимость — та же
`article_unit_costs` (снимок 05-20) через артикул WB: проверить по таблице,
что артикулы WB в снимке есть, и какая доля выручки выкупов WB за сентябрь
закрывается снимком (только чтение).

Проверка доступа: по одному обращению на эндпоинт с текущим токеном
(отчёт реализации за одну неделю сентября, статистика рекламы за один день) —
что отвечает: 200 / 401 / 403; горизонт отчёта реализации (самая ранняя
доступная дата — одним обращением). Итог §2 — план пятой задачи: какие
загрузчики писать, в какие таблицы, какие права токена нужны от владельца.
