# Входящая задача — WB

Сюда советник кладёт задачу для рабочей сессии по Wildberries. Сессия
читает этот файл и выполняет то, что в нём написано, а отчёт пишет в
`docs/outbox_wb.md`. Правила обмена те же, что у Ozon-потока
(`docs/how-we-work.md`, раздел «Порядок обмена»): одна задача за раз,
файл переписывается целиком, пока задача в работе — советник его не
трогает; вопрос посреди задачи — в `outbox_wb.md` блоком «вопрос, задача
не закончена».

`docs/inbox.md` и `docs/outbox.md` — канал Ozon-сессии. Не читать как
задачу и не писать туда.

Следующий кусок затрат WB, который у нас только дневным итогом без артикула: **платная приёмка** (`paid_acceptance` отчёта реализации) и **удержания** (`deduction`, за сентябрь 52 980 ₽, строки без `nm_id`). Та же схема, что у хранения (WB-18): загрузчик, таблица через `db_migrate`, ночной нефатальный шаг, сверка с отчётом реализации. ### §2. Удержания — что это по строкам

`wb_sales_report_rows` строки с `deduction ≠ 0` (без `nm_id`): `bonus_type_name`, `seller_oper_name`, `doc_type`, даты — таблица по видам за апрель … октябрь с Σ; какие виды привязать можно (например, «удержание за … по артикулу» в тексте) и какие нет. Это отчёт владельцу, кода не требует; если у WB есть отдельный метод по удержаниям (`deductions` в `12-reports.yaml`) — разведка одним запросом по слову.

## 2026-10-23, двадцатая задача WB: реклама и хранение WB по артикулам — в витрину `daily_sku_kpi` (пока только план, запись по слову)

§1 План без записи: (а) `storage_cost` WB = Σ `wb_paid_storage_daily` по (день, nmId); (б) `ad_spend` WB = `wb_ad_spend_nm_daily` по (день, nmId) — правило для разницы nms − updSum (1,3 %): либо масштабировать к updSum дня по кампании, либо брать nms как есть и показать расхождение; предложить одно, с числами за сентябрь; (в) «прочее» по SKU — только «Списания за отзыв» (nmId в тексте), остальное без артикула — не класть; (г) витрина WB-строк: сколько ключей (день, nmId) получат ненулевые колонки, Σ по месяцам против книги («Реклама» = Σ `upd` Баланс; хранение = форма «Выкупы WB») — таблица «месяц | реклама витрина | реклама книга | Δ | хранение витрина | хранение книга | Δ»; (д) где читать: `reports_daily_sku_kpi.py` — новые читатели по образцу `load_placement` (нечитаемая таблица → источник помечен, колонка 0, прогон не падает); `sql/` не нужен (колонки есть).
