# Входящая задача — WB

Сюда советник кладёт задачу для рабочей сессии по Wildberries. Сессия
читает этот файл и выполняет то, что в нём написано, а отчёт пишет в
`docs/outbox_wb.md`. Правила обмена те же, что у Ozon-потока
(`docs/how-we-work.md`, раздел «Порядок обмена»): одна задача за раз,
файл переписывается целиком, пока задача в работе — советник его не
трогает; вопрос посреди задачи — в `outbox_wb.md` блоком «вопрос, задача
не закончена».

`docs/inbox.md` и `docs/outbox.md` — канал Ozon-сессии. Не читать как
задачу и не писать туда.

### §2. Доля соинвеста WB по месяцам — функция в контракте модуля (сначала, коротко)

Ozon-скрипту (41-я задача) нужна доля соинвеста WB по месяцу для строк заказов без измеренной цены покупателя: формула P
владельца по отчёту реализации — `(Σ retailPriceWithDisc − Σ retailAmount) / Σ retailPriceWithDisc` по строкам «Продажа»
(возвраты — как в мосте) по `saleDt` МСК месяца. Добавить `coinvest_share_by_month(month_from, month_to, sb=None, rows=None)
-> {ярлык месяца: Decimal, "итого": Decimal}` рядом с `buyout_rate_for_finrez` (то же чтение отчёта узким `SELECT` по ключу),
тест на фикстуре (продажа + возврат + полночь МСК), живой прогон апрель … сентябрь — числа в отчёт (в WB-6 по сентябрю
1 … 21 P ≈ 0,32 — сверить порядок). Если Ozon-скрипт к этому моменту посчитал долю у себя — не страшно, функция всё равно
в контракт: одно определение в одном месте; расхождение с его цифрой, если будет, — в отчёт.

### §3. Выкуп WB в отчётах 7/60 дней и витрине — когорта вместо календарного

По твоей таблице «кто читает»: `daily_marketplace_kpi.buyout_rate` (WB) и `report_7_days` / `report_60_days` показывают
календарное «выкупы по дню продажи / созданные `marketplace_orders`» — 1,27 за 09-25, 0,95 за сентябрь при когорте 0,37 … 0,50.
Сделать в ветке: для строк WB витрины `daily_marketplace_kpi` (и `daily_sku_kpi`, если поле там читают) — `buyout_rate`
из `wb_buyout_cohort_daily` (зрелый — `rate_rub`, незрелый — `forecast_rate_rub` с признаком), старое значение — в
отдельное поле `buyout_rate_calendar` или не писать вовсе (решить по читателям: `report_management`, `export_management_excel`,
`reports_sku_*` — Ozon-строки не трогать); подписи в отчётах 7/60 дней — «выкуп по когорте». Миграция колонки, если нужна, —
по слову; ночь перепишет витрину сама (KPI-шаг). План «что изменится в отчёте 7 дней» — числами до / после.
