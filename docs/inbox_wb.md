# Входящая задача — WB

Сюда советник кладёт задачу для рабочей сессии по Wildberries. Сессия
читает этот файл и выполняет то, что в нём написано, а отчёт пишет в
`docs/outbox_wb.md`. Правила обмена те же, что у Ozon-потока
(`docs/how-we-work.md`, раздел «Порядок обмена»): одна задача за раз,
файл переписывается целиком, пока задача в работе — советник его не
трогает; вопрос посреди задачи — в `outbox_wb.md` блоком «вопрос, задача
не закончена».

`docs/inbox.md` и `docs/outbox.md` — канал Ozon-сессии. Не читать как
задачу и не писать туда.

### §2. Лист «Выкупы WB» книги «Фин рез» — модуль `scripts/report_finrez_wb.py`

Книгу собирает Ozon-скрипт `scripts/report_finrez.py` (тридцать седьмая §2) и импортирует
твой модуль; сигнатуры договорные: `build_rows(month_from, month_to) -> строки «Данные»`,
`build_month_sheet(rows) -> таблица по месяцам`, `build_split(rows, by='brand'|'category')`,
`SHEET_COLS`. Пока его скрипта нет — свой `--xlsx` для приёмки.

1. **«Данные WB выкупы»** — строка на (дата продажи `saleDt` МСК, nmId): Дата · Месяц (`апр` …)
   · Площадка (WB) · Магазин (кабинет) · Артикул · nmId · Наименование · Бренд (по букве) ·
   Категория (`subject_name` → список владельца: Кольца, Серьги, Подвески, Цепочки, Браслеты,
   Пирсинг, Колье, Броши; остальное — «прочее», счётчик) · Продажи ₽ (Продажа − Возврат,
   `retailPriceWithDisc`) · Реклама ₽ (§3; до него — по дню из `wb_ad_spend_daily`, разнесено
   по артикулам пропорционально продажам дня, с пометкой «разнесено») · Комиссия ₽ (Σ цена ×
   кВВ строки) · Логистика ₽ (`deliveryService` + `rebillLogisticCost`) · Себес-ть ₽ (СС × шт)
   · Хранение ₽ (`paidStorage`) · Ост. расходы и компенсации ₽ (`penalty` + `deduction` −
   `additionalPayment`, знак как у владельца) · Эквайринг ₽ (`acquiringFee`, возврат минус) ·
   Соинвест ₽ (Σ price − Σ retailAmount) · Штуки. Строки отчёта без nmId-продажи (хранение,
   штрафы без товара) — строка с пустым артикулом «(без товара)», чтобы Σ = «WB - месяц».
2. **«Выкупы WB»** — строки: месяцы и «Итого»; колонки ровно как у владельца: Продажи ₽ ·
   Комиссия ₽ · Себес-ть ₽ · Реклама ₽ · Хранение ₽ · Логистика ₽ · Ост. расходы и
   компенсации ₽ · Оборот (с НДС) · Комиссия (с НДС) · Комиссия % · Выручка без НДС ·
   Себестоимость · Маржа · Мар-ть % · Логистика без НДС · % · Реклама без НДС · % ДРР ·
   Эквайринг · % · Прочее без НДС · Фин. рез. · %. У владельца эквайринг 0 — у нас
   заполнен, единственное отличие формы, в подвале сказать. Разрезы бренд × месяц и
   категория × месяц.
3. Приёмка числами: Σ за 1 … 21.09 = итог «WB - сентябрь» по обороту, комиссии, логистике,
   эквайрингу, прочему, СС, фин. резу — до копейки (с поправкой на хранение, которое на
   месячном листе внутри «прочего» — показать разложение); август — против нашего «WB -
   август» (`report_wb_month.py --month 2026-08`); Σ брендов = Σ категорий = общий; строки
   «Данные» = ключей (день, nmId) с продажей + строк без товара.

### §3. Реклама WB по артикулу — источник и план

`adv/v1/upd` даёт списания по кампаниям, для разреза по артикулу нужна статистика по
номенклатурам: `adv/v3/fullstats` (спека `08-promotion.yaml`: ids ≤ 100 за запрос, период,
`nms[].sum` по дням) — проверить лимиты и глубину истории по спеке и одной пробой (1–2
обращения за 09-01 … 09-07 по активным кампаниям). Таблица `wb_ad_spend_nm_daily` (день,
advert_id, nm_id, sum, views, clicks, orders, …) — миграция по слову; загрузчик — в шаг
«WB: реклама» (та же строка), только за дни, где в `wb_ad_spend_daily` есть списания
(сентябрь — 0 обращений); бэкфилл февраль–август: посчитать обращения (кампаний 415 × дни —
через `ids` пачками по 100 и период ≤ 31 день) и время, план — в отчёт, запуск по слову.
Тождество: Σ `nms.sum` по дню ≈ Σ `updSum` по дню — измерить на июле (расхождение
объяснить: НДС, кэшбэк, без-nm списания). До таблицы — «Реклама ₽» в «Данных» разнесена, §2.
