# Входящая задача — WB

Сюда советник кладёт задачу для рабочей сессии по Wildberries. Сессия
читает этот файл и выполняет то, что в нём написано, а отчёт пишет в
`docs/outbox_wb.md`. Правила обмена те же, что у Ozon-потока
(`docs/how-we-work.md`, раздел «Порядок обмена»): одна задача за раз,
файл переписывается целиком, пока задача в работе — советник его не
трогает; вопрос посреди задачи — в `outbox_wb.md` блоком «вопрос, задача
не закончена».

`docs/inbox.md` и `docs/outbox.md` — канал Ozon-сессии. Не читать как
задачу и не писать туда.

main..HEAD`). Конфликты — назвать по файлам. Затем весь набор тестов: в
`main` сегодня 640, плюс твои `test_wb_*` — ожидание около 680, число

### 3. План восстановления — без единого обращения

`scripts/wb_orders_history_restore.py --plan`: дат, заказов и ₽ в базе по
ним, ожидание из runbook (+14 600 заказов и ≈ +360 млн ₽, коридор
10,7–18,8 тыс / 265–466 млн), время при паузе 65 с (~2 ч 51 мин на 158
дат), даты глубже 186 дней — отдельной строкой. Плюс то, чего в runbook
нет: сколько ключей `daily_sku_kpi` по WB за эти даты перепишет пересчёт
витрин и есть ли ключи, которые после восстановления останутся без
источника (как у Ozon в двадцать второй — там их пришлось удалять
отдельно).

Порядок из runbook не переставлять: сначала окно записи в проде (мерж),
потом снимок, потом восстановление, потом витрины. В этой задаче — только
план.
