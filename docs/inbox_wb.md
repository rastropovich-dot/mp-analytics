# Входящая задача — WB

Сюда советник кладёт задачу для рабочей сессии по Wildberries. Сессия
читает этот файл и выполняет то, что в нём написано, а отчёт пишет в
`docs/outbox_wb.md`. Правила обмена те же, что у Ozon-потока
(`docs/how-we-work.md`, раздел «Порядок обмена»): одна задача за раз,
файл переписывается целиком, пока задача в работе — советник его не
трогает; вопрос посреди задачи — в `outbox_wb.md` блоком «вопрос, задача
не закончена».

`docs/inbox.md` и `docs/outbox.md` — канал Ozon-сессии. Не читать как
задачу и не писать туда.

### §2. Ярлыки категории и бренда — одни на обе площадки (ветка `wb-fixes`)

Советник прочитал «Данные заказы» собранной книги: у Ozon-строк категория «серьги», «кольца» …, бренд «KARATOV» /
«Топаз»; у WB-строк — «Серьги», «Кольца» …, бренд «KARATOV» / «КОЮЗ Топаз». Сводная владельца по «Статус» и «Бренд»
раздвоит каждую категорию и бренд Топаз на две строки. Чинится в модуле, Ozon-сторона не трогается:

1. Категория — словарь владельца в его написании, как у Ozon (`ozon_product_catalog.OWNER_CATEGORIES`): `кольца ·
   серьги · подвески · цепочки · браслеты · пирсинг · колье · броши`, остальное — `прочее`; строчными. `CATEGORY_BY_SUBJECT`
   переписать на эти значения; `CATEGORY_UNKNOWN` («прочее (нет предмета)») после keyset-словаря почти пуст — оставить,
   но в отчёт число строк с ним. Не импортировать из Ozon-скрипта, продублировать кортеж с тестом на равенство
   множеству `OWNER_CATEGORIES` (тест читает `scripts/ozon_product_catalog.py` из основного дерева; если из worktree не
   читается — константа с пометкой, откуда).
2. Бренд — по первой букве артикула, как подтвердил владелец (`t` → Топаз, иначе KARATOV): ярлык **«Топаз»**, не «КОЮЗ

   артикула первична, `brand_name`/`brand` воронки — только когда артикула нет, и тогда нормализовать («КОЮЗ Топаз» →

### §3. Коэффициент выкупа WB — для листа «Коэффициенты» (сейчас там «WB — пусто»)

В форме владельца «Коэффициенты» — две таблички: `МП / % выкупа` (его образец: Ozon 0,84, WB 0,86 — чужой кабинет) и
`МП / Комиссия`. Ozon-скрипт заполняет Ozon (62,98 % измерено), для WB у модуля коэффициента нет. Дать его:

1. Измерить по нашим данным, только чтение: по месяцам апрель … август (сентябрь — незрелый) — `% выкупа` = Σ продаж
   отчёта реализации по `saleDt` / Σ заказов воронки (`orderSum`) того же месяца, в ₽ и в штуках (`buyout_count`/`order_count`
   воронки — второй способ, сравнить); плюс то, что считает ночной `buyout_rate` (в алерте 0,9562 = 589 / 616 за 1 … 22.09 —
   что у него в числителе и знаменателе, по коду). Три числа на месяц в отчёт, расхождения объяснить (лаг доставки:
   заказ в одном месяце, продажа в следующем — оценить долю по `saleDt − orderDate`, если дата заказа в отчёте есть).
2. В контракт модуля — `buyout_rate_for_finrez(month_from, month_to, sb=None) -> {month_label: Decimal, "итого": Decimal}`
   по способу, который ты обоснуешь (по умолчанию — ₽ по зрелым месяцам); Ozon-скрипт подхватит его в «Коэффициенты»
   следующей задачей — сюда только функция и тест. «Свод» WB считать по-прежнему с выкупом 100 % (формула владельца K
   = orderSum × 0,58 / 1,22) — менять только по его слову; вопрос ему — в отчёт одной строкой.
