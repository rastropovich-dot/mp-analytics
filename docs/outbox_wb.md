### 3. План восстановления

`python3 scripts/wb_orders_history_restore.py --plan` — ни одного обращения к WB:

Дат старше окна: 176 (2026-02-04 … 2026-08-21)
В базе по ним: 26,729 заказов / 680,616,255 ₽
В очередь этого прогона: 176 дат ≈ 190 мин при паузе 65 с
⚠️  Глубже проверенных 186 дней: 20 дат (2026-02-04…2026-03-18), 135 заказов / 5,206,964 ₽

Перед запуском пришлось чинить сам план: `stored_dates` читал 23 тыс. строк
`range()` без `order()` — дефект из how-we-work от 09-15. Теперь сортировка по
полному ключу, повтор ключа — отказ, Decimal, пустая сумма роняет (`6fd1c7f`).

  путём; у WB копейки бывают. Правка в `loaders/wb_orders_loader.py` — поведение
  ночного шага, без слова не трогал;
* **одно имя — два смысла**: у Ozon с 09-17/18 `orders_*` — подтверждённые,
  отмены в `cancelled_orders_*`; у WB `orders_*` — созданные вместе с отменёнными
  (51 % на пробах), `cancelled_orders_*` пусты (0 строк). Любая строка «заказы
  обеих площадок» складывает разное.
