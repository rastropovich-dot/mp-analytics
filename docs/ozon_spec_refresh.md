# Как обновить спеки Ozon

`docs.ozon.ru` блокирует машинные запросы — ни `curl`, ни агент оттуда
ничего не скачают. Спеку снимают руками из браузера. Занимает пять минут.

Обновлять, когда Ozon объявляет новые методы или меняет контракт; раз в
пару месяцев без повода тоже не лишнее.

## Один раз: включить инструменты разработчика в Safari

Настройки Safari → вкладка **Дополнения** (крайняя справа) → галочка
**«Показывать функции для веб-разработчиков»**. В строке меню появится
пункт «Разработка».

В Chrome ничего включать не нужно, инспектор там доступен сразу.

## Снять спеку

1. Открыть страницу документации:

       Seller API        https://docs.ozon.ru
       Performance API   https://docs.ozon.ru/api/performance

2. `⌥⌘I` — открыть веб-инспектор
3. Вкладка **Сеть** (Network)
4. `⌘R` — перезагрузить страницу, чтобы запросы попали в список
5. В поле фильтра инспектора набрать `json`
6. Найти нужный файл: он самый крупный из json, сотни килобайт или
   мегабайты. Для ориентира — Seller API весит около 4 МБ, Performance
   около 300 КБ
7. Правый клик по файлу → **Сохранить как**

## Проверить, что снялось то самое

Типичный провал — вместо спеки сохраняется HTML страницы-ошибки или
обёртка, похожая по размеру на настоящий файл.

    python3 -c "
    import json,sys
    d=json.load(open(sys.argv[1]))
    print(d['info']['title'], '| openapi', d['openapi'])
    print('методов:', len(d['paths']), '| схем:', len(d['components']['schemas']))
    print('сервер:', d['servers'][0]['url'])
    " ФАЙЛ.json

Должно напечатать заголовок, `openapi 3.0.0` и ненулевое число методов.
Ошибка парсинга или `методов: 0` означают, что файл не тот.

Ориентиры на 2026-09-13:

    Seller API        466 методов, 2154 схемы, v2.1, api-seller.ozon.ru
    Performance API    47 путей (48 операций), 97 схем, v2.0, api-performance.ozon.ru  ← пересняли 2026-09-17

Заметное падение числа методов — повод остановиться и проверить, а не
класть файл в репозиторий.

## Через встроенный браузер Claude (Performance, проверено 2026-09-17)

`curl` блокируется, но страница документации сама запрашивает
`https://docs.ozon.ru/api/performance/swagger.json` (видно в сетевых запросах
вкладки). Сессия открывает `https://docs.ozon.ru/api/performance/` во
встроенном браузере и из контекста страницы делает `fetch('/api/performance/swagger.json')`.
Файл 265 КБ; чтобы не тащить его через контекст целиком, сначала считать
дайджест (число путей и операций, хеш описания каждой операции, текст тега
Limits) и сравнить с копией в репозитории, а полный файл забирать gzip +
base64 (~43 КБ) и раскладывать на диске: `base64 -D -i файл | gunzip`
(на macOS `base64 -d ФАЙЛ` не работает — аргумент только через `-i`).
Скорее всего у Seller API есть свой `swagger.json` по тому же образцу — не
проверяли.

## Положить в репозиторий

    spec/ozon-seller.json
    spec/ozon-performance.json

Имена не менять — на них ссылаются `CLAUDE.md` и рабочие сессии.

Перед коммитом посмотреть, что изменилось:

    git diff --stat spec/

Если менялись методы, которые мы зовём, — сказать об этом в отчёте, а не
коммитить молча. Ozon однажды переименовал колонки цен без объявления.
