## 0. Что в листе у владельца (как есть)

Блок «Выкупы WB», строки 4–34, колонки A–S. Формулы владельца:

```
D  Комиссия %   = C / B                              ← 0,42 на 14 днях из 21, 0,4163…0,4198 на остальных
E  Выручка      = (B − C) / 1,22 − [свод]!AB{r+1}     ← вычет «НДС за возмещение», 1…21.09 = 88 946,47
G  Маржа        = E − F
P  Фин. рез.    = G − I − K − M − O
R  Ebitda       = P − $T$81                           ← T81 = 74 002,00 в день
```

Числа (B, C, F, I, K, M, O) — вбиты (формулы в ячейках проверены 2026-09-23:
C4 = 527486.82 — число, не формула); I, M, O — с хвостом `/1,22`, то есть
пересчитаны из сумм с НДС. **«C — константа 42 % от B» — опровергнуто 2026-09-23
(WB-5 §3):** C = Σ `retailPriceWithDisc` × `commissionPercent` / 100 по строкам

21 из 21 до копейки. На 09-05 (три строки 43 %, одна 39,5 %) это 447 569,17
против 447 777,54 у константы. Итоги 1…21: оборот 16 667 220,00, комиссия

## 2. Колонка → поля отчёта (по дню продажи `saleDt` МСК, суммы по дню)

|---|---|---|
| **B Оборот (с НДС)** | Σ `retailPriceWithDisc` × (+1 Продажа / −1 Возврат) по `sellerOperName ∈ {Продажа, Возврат}` | **7 из 7 дней до рубля** (1 255 921, 1 621 368, …). Это же = `priceWithDisc` из `supplier/sales` = `marketplace_buyouts.buyouts_amount_seller`: 1…21.09 — 16 667 220 в базе и в листе |
| **C Комиссия (с НДС)** | **Σ `retailPriceWithDisc` × `commissionPercent` / 100, Продажа +, Возврат −** (кВВ строки; 1…21.09 — 21 из 21 до копейки, найдено 2026-09-23). **Решение советника 2026-09-23: колонка «Комиссия» нашего листа — она же (как у владельца); `B − Σ forPay±` — справочная колонка «удержано из выплаты всего», не комиссия** (в ней ещё согласованная скидка и доплаты). Прежнее «константа 0,42 × B» — опровергнуто: 42 у большинства строк, 38 / 39,5 / 43 у части. Разложение факта: «согласованная скидка» `retailPriceWithDisc − retailAmount` = 43,37 % + (`retailAmount − forPay`) ≈ 1,05 % | тождества нет по построению; факт измерен |

## 4. Себестоимость: артикулы WB в снимке 1С

`supplierArticle` WB = базовый артикул (`F000287741`), размер — отдельно в
`techSize` (`'0'`, `'17'`, `'17,5'`, `'45'` …). В снимке `offer_id` — вариант
`артикул-размер` (`F000287741-17,5`, запятая как в WB) или без размера для
безразмерных; у одного артикула 8–20 вариантов, и **себестоимость по размерам
разная** (`F000287741`: 14 765,41 … 19 903,50; `T000066064`: 34 343,77 …
59 717,50), `unit_cost_uniform` — одна на артикул (17 414,44 и т. д.).

Покрытие выкупов WB за 1…21 сентября (486 строк, 257 артикулов, 586 позиций,
оборот 16 667 220):

| стыковка | артикулов | оборот | доля |
|---|---:|---:|---:|
| точное совпадение `lower(article)` = `offer_id_norm` (только безразмерные) | 119 из 257 | 4 117 385 | 24,7 % |
| базовый артикул есть в снимке (любой вариант) | **225 из 257** | **15 765 032** | **94,6 %** |
| базового артикула в снимке нет | 32 | 902 188 | 5,4 % |

Значит СС считается по варианту `vendorCode + techSize` (оба есть в каждой строке
отчёта реализации и в `supplier/sales`), с откатом на `unit_cost_uniform` там, где
варианта нет; из `marketplace_buyouts` этого не собрать — размера нет.
Себестоимость владельца 1…21 — 5 943 927,07 (35,7 % оборота); по нашему снимку и
позициям без размера не сравнить, сравнение — после загрузчика. Снимок 05-20;
владелец считает по своим ценам 1С («на 16 % выше нашего снимка» у Ozon,
`cost_of_goods.md`).

## 6. Лента заказов и `isCancel` (задача §3)

времени текущего статуса** (`updatedAt`), 1 запрос/мин, пагинация `offset` +

получении, и истёкший срок — гипотеза 09-21 подтверждена данными ленты (71 %
отмен дня — отказ при получении). На `cancelled_orders_*` это ложится так:

## 15. Коэффициент выкупа WB для листа «Коэффициенты» — `buyout_rate_for_finrez` (WB-9 §3, 2026-09-25)

Форма владельца — табличка «МП / % выкупа» (его образец: Ozon 0,84, WB 0,86 — другой кабинет). У Ozon-скрипта коэффициент
измерен по подтверждённым / созданным ₽ дозревших дней; у WB подтверждения нет, есть продажа. Четыре способа посчитать,
все только чтение (`wb_sales_report_rows`, `wb_funnel_products_daily`, `marketplace_orders_analytics`, `marketplace_orders`),
числа апрель … август 2026 — в outbox, девятая:

* **календарный** — Σ продаж отчёта по `saleDt` месяца / Σ `orderSum` воронки того же месяца: смешивает когорты — 11 … 35 %
  продаж месяца по ₽ приходятся на заказы прошлого месяца (апрель 13,8 %, август 34,8 %; лаг `saleDt − orderDt` p50 3,0 … 3,9 дн.
  в апреле … июле, 7,0 в августе, 8,3 в сентябре; p90 7,7 … 9,0 / 15,1 / 23,8);
* **когорта месяца заказа** (принят) — Σ продаж отчёта (Продажа − Возврат, `retailPriceWithDisc`) по месяцу `orderDt` МСК / Σ
  `orderSum` воронки того же месяца (`marketplace_orders_analytics` = Σ `wb_funnel_products_daily` по месяцам до рубля); в
  штуках — второй способ. Совпадает с собственным `buyoutSum` / `orderSum` воронки по дню заказа (апрель до рубля, дальше
  расходится на 0,02 … 0,8 % — воронка считает продажу раньше отчёта и не всегда снимает возврат);
* **воронка** — `buyoutCount` / `orderCount` по дню заказа (то же, в штуках);
* **ночное правило** `buyout_rate` алерта — `buyouts_qty` (по `saleDt`) / (`orders_qty` + `cancelled_orders_qty`) из
  `marketplace_orders` (`supplier/orders`, не воронка): по коду `reports_daily_sku_kpi.buyout_rate` и
  `created_orders_qty`; числитель календарный, знаменатель — другой источник, помесячно даёт 0,41 … 0,74 и для
  коэффициента не годится.

Зрелость: когорта месяца дособрана к 25-му дню после конца месяца — апрель … июль 99,95 … 100,1 % итога по ₽ (выше 100 %
— поздние возвраты), к 10-му дню 97,6 … 99,4 % (`BUYOUT_RATE_MATURE_DAYS = 25`). Функция отдаёт только зрелые месяцы и
«итого» по ним (Σ числителей / Σ знаменателей), незрелые — в `details` с `mature=False`; отчёт читается с 1-го числа
`month_from` по сегодня (продажа заказа проходит и через 40 дней после конца месяца). «Свод» WB по-прежнему с выкупом 100 %
(K = `orderSum` × 0,58 / 1,22) — менять только по слову владельца.

## 16. Выкуп WB по когорте — для витрины и алерта (WB-10 §2, 2026-09-25)

Ночное правило `reports_daily_sku_kpi.buyout_rate` (= `buyouts_qty` по дню продажи / созданные `orders_qty` +
`cancelled_orders_qty` из `marketplace_orders` по дню заказа) для WB метрикой выкупа не является: числитель и знаменатель
— разные дни и разные источники; помесячно апрель … август 0,52 / 0,43 / 0,41 / 0,61 / 0,74 против когорты 0,52 / 0,51 /
0,48 / 0,53 / 0,42, по дню 0,33 … 2,0. Читатели старых полей (алерт — `buyouts_qty` рядом с заказами дня; отчёты 7/60
дней; `report_management` / `export_management_excel`; слой решений — `buyout_rate_rolling_14d/30d` по подтверждённым)
считают их календарными, поэтому старые поля не переписываются, когорта живёт в своих таблицах
(`sql/20260926_create_wb_buyout_cohort.sql`, по слову):

* `wb_buyout_cohort_sku_daily` (день заказа, nmId): `created_qty/sum` из воронки, `sold_qty/sum` — продажи отчёта по
  `orderDt` МСК (Продажа − Возврат), `age_days`, `mature` (≥ 25 сут.), `rate_qty/sum` — только у зрелых;
* `wb_buyout_cohort_daily` (день): Σ по nmId; у незрелых дней — `forecast_rate_*` = Σ sold / Σ created по зрелым дням
  последних 30 суток (`forecast_window`, календарное окно от последнего зрелого дня назад).

Код — `loaders/wb_buyout_cohort.py` (чистые функции, читатели: отчёт узким `SELECT` по ключу с первого дня окна по сегодня,
воронка фильтром «карточки с заказами»), шаг — `scripts/wb_buyout_cohort_step.py` (`--plan`, `--dry-run`,
`--apply --approve-wb-cohort-write`; окно ночи 60 дней ≈ 4 200 ключей, ~10 страниц). Тождество с коэффициентом листа
(`buyout_rate_for_finrez`, §15) — до 0,0001 на всех зрелых месяцах апрель … август 2026 (₽ и штуки): одно определение —
одно число. **В проде с 2026-09-25 по слову** (`main` `329fe77`): таблицы созданы и заполнены за 04-01 … 09-24 (22 719 ключей, 177 дней), шаг
«WB: выкуп по когорте» идёт после «WB: отчёт реализации» (нефатальный, окно 60 дней), алерт печатает в блоке «WB вчера» строку
«Выкуп по когорте: <последний полный зрелый месяц> XX,X % (зрелые дни ≥ 25 сут.), прогноз для последних 30 дней YY,Y % по зрелым
DD.MM … DD.MM» (`alerts_telegram.format_wb_buyout_cohort`; таблицы нет — строка с причиной), книга модуля — подпись
`buyout_rate_caption`. Первая ночь шага — 09-26.

## 17. Лаг заказ → продажа: с 10 августа всё едет со «Склада WB» (WB-10 §4, только чтение)
