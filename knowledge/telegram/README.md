# Чат разработчиков Ozon

`ozon-dev-chat.json` — экспорт публичного чата Ozon for dev из Telegram.

    чат        General (public_supergroup), id 1677162135
    сообщений  38 059 (базовый экспорт 37 863 + 123 + 38 + 35)
    период     2022-05-13 … 2026-09-17
    пропусков  нет ни одного месяца
    снято      2026-09-13, дополнено 2026-09-15 и дважды 2026-09-17 (последнее сообщение 19:59)

## Зачем

Источник ответов о поведении Ozon API: недокументированные ограничения,
реальные сроки отключения методов, ответы поддержки, обходные пути.
Брать ответы отсюда, а не спрашивать владельца.

Второй источник рядом — `spec/` с OpenAPI-спеками. Спека говорит, что
метод обещает; чат говорит, как он ведёт себя на самом деле.

## Как искать

Файл большой (30 МБ), целиком не читать. Искать по нему скриптом:
фильтровать `messages` по подстроке в `text`, возвращать дату, автора
и текст. У каждого сообщения есть `id` — по нему сообщения связываются
через `reply_to_message_id`, так что ветку обсуждения можно собрать.

Поле `text` бывает строкой, а бывает списком фрагментов (когда есть
ссылки или код) — обрабатывать оба случая, иначе часть сообщений
потеряется при поиске. Ссылки лежат отдельными фрагментами с
`type: link` или `text_link`; сам адрес — в `href`.

## Вложения

Пути в полях `photo` и `file` заданы относительно корня экспорта.
Корень **один**, лежит вне репозитория, на машине владельца:

    ~/Downloads/Telegram Desktop/ChatExport_2026-09-13/

    result.json                                    базовый экспорт
    chats/chat_562951630583447/topic_1/photos/     2 532 фото, 135 МБ
    chats/chat_562951630583447/topic_1/files/        476 файлов, 34 МБ
    chats/chat_562951630583447/topic_1/voice_messages/   1 файл

Всего 198 МБ. В репозиторий не кладём — здесь только JSON.

Чтобы открыть вложение: взять путь из поля `photo` или `file` и
приписать к нему корень выше. Проверено 2026-09-17 (вечер): все 2 823 пути
из JSON разрешаются под этим корнем, ни одного промаха.

73 файла не выгрузились из-за ограничения Telegram на размер — в JSON у
них вместо пути стоит текст в скобках, а не путь. Отличать по первому
символу `(`.

**Ловушка при обновлении.** Каждый новый экспорт кладёт свои вложения в
свой корень (`ChatExport_2026-09-15`, `ChatExport_2026-09-17`, …), а имена
внутри сквозные: `photo_2555@…`. Слить один JSON мало — пути новых
сообщений будут указывать в корень, которого README не знает, и вложение
не откроется, хотя файл на диске есть. Поэтому при каждом слиянии
вложения нового экспорта **копируются в корень 09-13**, и он остаётся
единственным. Так сделано 2026-09-17: перенесено 11 фото (шесть из
экспорта 09-15, пять из 09-17), вечером ещё одно (`photo_2560`, второй
экспорт 09-17). Столкновений имён не было и быть не должно — нумерация
сквозная.

Папка в Загрузках недолговечна. Если её удалить, картинки пропадут, а
JSON останется со ссылками в никуда — тогда понадобится новый экспорт.

## Обновление

Экспорт — снимок на дату, сам не обновляется. Переснимать вручную:
Telegram Desktop → чат → меню → Экспорт истории чата → формат JSON.
Новый экспорт дописывать к старому по `id`, не заменять целиком.

Порядок слияния: сверить `id` и `name` чата, собрать оба снимка в
словари по `id`, обновить пересечение свежим снимком, добавить новое,
отсортировать по `id`, проверить, что ни один месяц не выпал, и только
потом писать — с резервной копией рядом.

Файл хранится с `indent=1` и `ensure_ascii=False` — так же, как его
отдаёт Telegram. Не переписывать компактным JSON: содержимое не
пострадает, но файл станет одной строкой и `git diff` перестанет
показывать, что именно изменилось.

Уже сделано:

    2026-09-15  инкремент 09-07 … 09-15, 494 сообщения, id 65419 … 66090
                новых 123, пересечение 371, изменились 17
    2026-09-17  инкремент 09-13 … 09-17, 194 сообщения, id 65876 … 66166
                новых 38, пересечение 156, изменились 3 (только реакции)
    2026-09-17  второй инкремент, 72 сообщения, id 66094 … 66258
                новых 35, пересечение 37, изменившихся 0; проверено против
                версии в git: потерь 0

Резервная копия перед слиянием — `ozon-dev-chat.json.bak`, сами
инкременты — `_increment_ГГГГММДД.json`; и то и другое в `.gitignore`.

То, что на пересечении сообщения меняются задним числом, стоит помнить:
слияние — не «дописать хвост», а «обновить пересечение и добавить
новое». В сентябре менялись только реакции, но в прошлый раз правок
было 17 из 371.
